# PDM — PostgreSQL Physical Schema `pct_analytics`

## 1. Purpose

This physical data model (PDM) describes the concrete implementation of the `pct_analytics` schema in PostgreSQL.

This schema is **generated by dbt** (materialized as tables or views) and consumed in read-only mode by the analytical API layer (Sprint 3).

---

## 2. Schema

```sql
CREATE SCHEMA IF NOT EXISTS pct_analytics;
```

---

## 3. Tables / Materialized Views

### 3.1 obt_sales

Central denormalized table — grain: **1 row = 1 sales transaction**.

```sql
CREATE TABLE pct_analytics.obt_sales (
    transaction_id      INTEGER NOT NULL,
    transaction_date    TIMESTAMP NOT NULL,
    product_id          INTEGER NOT NULL,
    store_id            INTEGER NOT NULL,
    price_id            INTEGER NOT NULL,
    promotion_id        INTEGER,
    quantity            INTEGER NOT NULL,
    unit_price          NUMERIC(12,2) NOT NULL,
    revenue             NUMERIC(12,2) NOT NULL,
    is_promo            BOOLEAN NOT NULL,
    price_scope         VARCHAR(20) NOT NULL,
    price_type          VARCHAR(20) NOT NULL
);
```

> **Note**: The dbt model may contain additional enrichment columns depending on the joins performed. The SQLAlchemy application model `ObtSales` currently maps only the columns required by the `/kpis` and `/anomalies` endpoints.

---

### 3.2 kpi_price_performance

Price performance KPI — grain: **1 row = 1 combination (country_id, store_id, product_id)**.

Main columns:

| Column | Type | Description |
|---|---|---|
| country_id | INTEGER | Country |
| store_id | INTEGER | Store |
| product_id | INTEGER | Product |
| current_revenue | NUMERIC(12,2) | Revenue current period (30d) |
| previous_revenue | NUMERIC(12,2) | Revenue previous period (30d) |
| revenue_change_pct | NUMERIC(8,4) | Revenue change (%) |
| current_avg_selling_price | NUMERIC(10,2) | Current average selling price |
| country_avg_selling_price | NUMERIC(10,2) | Country price benchmark |
| price_vs_country_benchmark_pct | NUMERIC(8,4) | Deviation vs benchmark (%) |
| performance_flag | VARCHAR(30) | Performance flag |
| benchmark_flag | VARCHAR(40) | Benchmark flag |

---

### 3.3 kpi_promo_performance

Promotional performance KPI — grain: **1 row = 1 combination (country_id, store_id, product_id, promotion_id)**.

Main columns:

| Column | Type | Description |
|---|---|---|
| country_id | INTEGER | Country |
| store_id | INTEGER | Store |
| product_id | INTEGER | Product |
| promotion_id | INTEGER | Promotion |
| promo_revenue | NUMERIC(12,2) | Revenue during promotion |
| baseline_revenue | NUMERIC(12,2) | Revenue before promotion (14d) |
| revenue_uplift_pct | NUMERIC(8,4) | Revenue acceleration (%) |
| quantity_uplift_pct | NUMERIC(8,4) | Quantity acceleration (%) |
| additional_revenue | NUMERIC(12,2) | Incremental revenue |
| promo_performance_flag | VARCHAR(30) | Promo efficiency flag |
| family_effect_flag | VARCHAR(20) | Family effect flag |

---

## 4. API Consumption

The `pct_analytics` schema is exposed via the SQLAlchemy `ObtSales` model (read-only) and consumed by:

| Endpoint | Usage |
|---|---|
| `GET /sales` | Transaction listing from `pct_core.sales_transaction` |
| `GET /kpis` | Dynamic aggregations on `pct_analytics.obt_sales` |
| `GET /anomalies` | Rule-based detection on `pct_analytics.obt_sales` |

---

## 5. Refresh

Data in `pct_analytics` is refreshed by running `dbt run`:

```bash
cd data/dbt && dbt run
```

Materialization (table or view) is defined in `dbt_project.yml`.
